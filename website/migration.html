Switch from Auth0 to auth2

Migrating from Auth0 is straightforward. auth2 uses the same OAuth 2.0 / OIDC endpoints and Auth0-style Management API, so most of your code stays the same.

1. Deploy auth2

Run auth2 on GCP Cloud Run, AWS ECS, or Docker. See DEPLOY.md for details.

# Quick start with Docker Compose (Postgres + Redis)
docker compose -f deploy/docker-compose.yml up -d

2. Configure issuer URL

Point ISSUER_URL to your auth2 instance (e.g. https://auth.yourdomain.com). This is the base URL for OIDC discovery, JWKS, and tokens.

3. Match application settings

In auth2, register your applications (clients) via CLIENT_REGISTRY env or Management API. Use the same client_id, redirect_uri, and allowed_scopes as in Auth0.

4. Export users from Auth0

Use Auth0's User Import/Export extension or Management API to export users. Auth0 stores passwords hashed — you'll need to use the Migration Guide for password migration, or trigger password reset on first login.

5. Import users into auth2

Use auth2's Management API to create users:

POST /api/v2/users
Content-Type: application/json
Authorization: Bearer YOUR_ADMIN_API_KEY

{
  "connection": "Username-Password-Authentication",
  "email": "user@example.com",
  "password": "SecurePassword123",
  "name": "User Name"
}

6. Update your application

Change the auth configuration in your app from Auth0's domain to your auth2 issuer URL. Example for a typical SPA:

// Before (Auth0)
domain: 'your-tenant.auth0.com'

// After (auth2)
domain: 'auth.yourdomain.com'
// or issuer: 'https://auth.yourdomain.com/'

7. Rules and custom logic

auth2 supports Auth0-style Rules (JavaScript). Place your .js files in RULES_DIR. Rules receive user and context and can add claims to tokens.

8. Social login

Auth0 supports Google, GitHub, etc. auth2 does not yet include social connectors. Options:

  • Use database connection only (email/password) during migration
  • Implement social as a custom OAuth proxy (on roadmap)

What stays the same

  • /authorize, /oauth/token, /oauth/revoke
  • /.well-known/openid-configuration, /.well-known/jwks.json
  • /userinfo, /tokeninfo
  • /api/v2/users, /api/v2/clients, /api/v2/roles
